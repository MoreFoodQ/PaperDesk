# Document formats

PaperDesk 0.2.0 supports PDF and a bounded subset of reflowable EPUB 2/3. Local file selection, drag-and-drop, and file paste accept both formats. URL, DOI, arXiv, and title lookup continue to retrieve PDFs.

## EPUB behavior

The importer reads the EPUB container and package metadata, then follows the spine's linear reading order. It preserves headings, paragraphs, basic list and table text, and embedded JPEG, PNG, GIF, and WebP images. Animated images use the first frame. External images become labeled placeholders and are never fetched.

Each chapter starts on a new reading page. Paragraphs wrap in a common layout using system fonts; publisher CSS, interactive links, and precise table layout are not retained. Navigation and block-level annotations work on the same model-generated blocks used for PDF. With **Do nothing yet**, both formats show source page images without a model call. **Read the original** organizes passages with a model and consumes quota; translation uses the configured target language.

The original `source.epub` is retained byte-for-byte and can be downloaded from the library or reader information panel. A locally generated `source.pdf` provides the existing reference-page workflow. This reading PDF consists of page images; extracted text and character anchors are stored separately for the app's model context and passage positioning. Its page numbers and layout are generated by PaperDesk, not original book pagination. Cite the original edition's location instead.

Translation, GPT conversations, notes, highlights, progress, and offline HTML export reuse the existing storage and reader operations. Model credentials and quota configuration are unchanged. Import deduplication and library migration verification hash the original EPUB rather than the generated PDF. PDF's original-file import and rendering path remain separate.

## Current limits

| Content or resource | Behavior |
|---|---|
| Reflowable EPUB 2/3 with UTF-8 XHTML chapters | Supported |
| Fixed-layout or non-XHTML spine content | Rejected with a format message |
| SVG, MathML, audio, video | Rejected; convert to PDF when these must be preserved |
| DRM, encrypted resources, obfuscated fonts | Rejected; no unlocking or decryption |
| Publisher scripts, styles, iframes, embedded objects | Not executed or rendered |
| Archive / expanded content / individual member | 32 MiB / 64 MiB / 8 MiB |
| Archive members / linear chapter references | 2,048 / 512 |
| Extracted text / reading pages | 500,000 characters / 200 pages |
| Included image bytes / pixels per image | 32 MiB / 16 million pixels |
| Worker concurrency / wall time / CPU / memory | 2 / 120 seconds / 60 seconds / 1.5 GiB |

Repeated image references also count toward the image-byte limit. Highly compressed entries are rejected to bound decompression. Actual worker resource limits may stop a book before the numerical content limits are reached. An import error never invokes a model automatically; a preparation error is visible in the library job state. There is no silent fallback for rejected format features.

Windows uses Microsoft JhengHei. Other environments need Noto Sans CJK or a compatible listed system font for Chinese content; Latin-only books may use DejaVu Sans. Missing fonts produce an error. Windows x64 is the validated distribution; this change does not extend the supported OS scope.

## Import safety

Archive members are read in memory rather than extracted. The importer rejects absolute and traversal paths, duplicate members, symlinks, encrypted entries, XML entity declarations, and unsafe archive sizes. EPUB processing runs in the existing resource-limited document worker. Publisher HTML is reduced to text and image data; it is not served as an application page. Original downloads require the same local authentication as other document files.

The worker uses the current OS user and is not an OS file-access sandbox. Model calls still send the selected text or page images through the configured CLI/API, just as PDF calls do. Importing a local book with model processing and metadata lookup disabled stays local.

## Verification

`python -m unittest tests.test_epub` covers synthetic EPUB 2/3, spine order, Traditional Chinese, tables and images, hostile archives/XML, explicit unsupported-format errors, pagination limits, PDF dispatch, original download identity, notes, text and vision translation paths, cancellation, chat context, offline export, and migration identity. Model calls are simulated.

`node scripts/verify_epub.cjs` is an optional browser integration check for mixed-format import, source page images, authenticated original download, note persistence after reload, and offline exports. It uses an isolated data directory and synthetic files. Configure the Playwright, browser, and Python overrides listed in the script header when needed.

EPUB structure follows the [W3C EPUB specification](https://www.w3.org/TR/epub-33/). Support for all EPUB features is not claimed.
